# Changelog

All notable, agent-relevant changes to the `@audiorective/*` packages.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
All packages are released together under one version (`bumpp -r --all`), so a
single version number covers the whole toolkit. Each entry names the package(s)
it affects so a reader can tell which dependency to upgrade.

This file exists so an agent (or human) hitting an "API not found / undefined /
type error" on a documented API can tell whether the installed package simply
predates that API. See the "Version mismatches" note in the skill.

## [3.0.0-beta.0] - 2026-11-27

### Added

- **clock, sequencer, host, widgets:** failures that were only logged to the console are now observable: `clock.error` (a scheduler's `schedule`, `reset` or `transport` hook threw), `seq.error` on `StepSequencer` (a lane `sound` failed or `onHit` threw), `host.cells.error` on `WebClapHost` (the plug-in reported an error, even with no call waiting), and `error` on the `mountPianoRoll` handle (`onNoteAdd`, `onNoteEdit` or `onNoteDelete` threw) and the `mountStepGrid` handle (a later `onCell` setup threw). Each is a `ReadonlyCell<Error | null>` holding the latest failure, null until one happens; the isolation is unchanged (the other schedulers, hits and registrations keep running) and the console still logs it. A thrown non-`Error` is wrapped (`Clock scheduler failed.`, `Step Sequencer hit failed.`, `Piano roll note edit failed.`, `Step grid cell attachment failed.`) with the value as `cause`.
- **core:** `ParamOptions.validate` and `cell(initial, { validate })` (also the `cell` build helper; new type `CellOptions`). The function throws to refuse a value: it runs on the initial value and before every `.value`, `$(x)` or `update` write, so a refused write is not stored and never reaches a `bind` target.

- **daw, mcp:** a stepped device parameter snaps instead of throwing. `project.setDeviceParameter` and the `setDeviceParameter` operation take any value from `min` to `max` on a `step: 1` parameter and apply the nearest whole step counted from `min` (a tie goes up: `53.9` applies as `54`); a value outside the range still throws. `project.setDeviceParameter` returns the value applied, and the `applyEdits` receipt (and the MCP `apply_edits` result) has `deviceParameters: [{ deviceId, parameterId, value }]`, one entry per `setDeviceParameter` operation in request order. The message `… is stepped and needs a whole number …` is gone. `read_automation` for a controller lane the track does not have returns `points: []` with a `note` instead of an error (an unknown track still errors), so the call that prepares a `setControllerLane` works.

- **daw, mcp:** device parameters. `workspace.deviceParameters(deviceId)` lists the parameters of a WebCLAP plug-in and of a built-in rack effect (`rackDeviceId(trackId, slotId)`) in one row shape (`id`, `name`, `kind`, `min`, `max`, `default`, `value`, `step?`, `unit?`, `text?`), tracked; `project.setDeviceParameter(deviceId, parameterId, value)` changes one, joins the Undo step and version of the surrounding `project.edit` or `applyEdits`, and a running Workspace applies it without a rebuild. `ProjectDevice.parameters` (new, optional in `addDevice`) is the device's parameter table: the song's value of each parameter, which wins over the values inside the saved state bytes and which a Workspace fills from the plug-in the first time it loads (no Undo step); a value the plug-in moves itself is stored there without an Undo step. `setDeviceState` empties the table. `applyEdits` has the operation `setDeviceParameter { deviceId, parameterId, value, expectedValue? }`: a different current value returns `conflict` with it in the reason. The MCP tool `read_device_params({ deviceId })` (category `read`) returns the rows, and `read_project` lists each device's parameter count and a built-in effect's `deviceId` under `effectDevices`. `saveDawProject` writes the table as the `ClapPlugin`'s `Parameters` (`RealParameter` with `parameterID`, `min`, `max`, `value`; default and step in `audiorective/host.json`) and `openDawProject` reads them. Exports `rackDeviceId`, `splitRackDeviceId`, `DeviceParameter`, `DeviceParameterRecord` and `SetDeviceParameterEdit`.
- **midi, daw:** a start, a seek, a loop wrap or the arrangement switched back on chases the position instead of resetting blindly. The devices are sent what the beat needs from every source (clip events before it within the clip's window and loop, track lanes, program change and bank select) and only what differs from what they were last sent, so a seek to bar 9 sounds the volume and pan an imported file set at bar 1 (live and `renderMixRange` agree) and a pedal held on both sides of a seek does not dip. A `MidiClip` window that begins mid-content (a clock start or seek past beat 0) does the same for its `messages`. Stop and pause still put performance controllers back to rest, but only a curated list rests (`controllerRestValue`: CC1, 2, 4, 7 (100), 8 and 10 (64), 11 (127), 64 to 69, 71 to 74 (64), pitch bend, pressure); bank select, data entry, increment and decrement, NRPN and RPN selectors and every other controller are never reset, so a stop no longer sets a pitch-bend range of 12 semitones to 0. `controllerRestValue` returns undefined for a controller without a rest value. New exports `controllerStateKey`, `chaseMessages` and `claimController` from `@audiorective/midi` (`claimController` lets a later owner of a controller, such as the Arrangement taking a track back from a Session clip, keep the value it sends instead of the clip's rest value). `MidiClip.playbackEvents()` in daw carries the latest bank select, program change, controllers, pitch bend and pressure to a window or loop pass start, and a track handed back from a Session clip to the Arrangement is chased to what the Arrangement needs there. A `MidiClip` whose instrument's `scheduleMidi` throws loses that one message, keeps scheduling the rest of the window and reports the first error once with `console.error`.
- **midi, daw:** a `MidiClip` sends controller, pitch-bend, program-change and pressure messages with its notes. New `messages` option, `clip.messages` cell and `clip.setMessages([{ beat, data }])`; an `Instrument` may add `scheduleMidi(data, when)` to receive them (an instrument without it plays the notes as before). At one time the order is note-offs, program changes, controllers, bend and pressure, then note-ons; a loop repeats the messages every pass; when the clip stops, is replaced or its transport stops, pauses or seeks, each controller it moved goes back to rest (sustain 0, bend centre, mod wheel 0, volume 100, pan 64, expression 127) unless a later clip took it over, and a message still ahead is withdrawn. A DAW Session MIDI clip now sends its own controllers, bend, program changes and pressure through this, exactly as the Arrangement sends them for the same content (the controller values before the clip's window are carried to its start and a pedal still down at a pass end is released there), so a Session clip with a pedal sounds the same live as in `renderSession` and on the Arrangement. Before, live Session sent notes only. New exported type `ClipMessage`.
- **mcp, daw:** `@audiorective/mcp` checks the page that connects. The handshake needs an allowed `Origin` (default: `http://localhost:*`, `http://127.0.0.1:*`, `http://[::1]:*`; `--allow-origin`, `allowedOrigins`), otherwise it gets HTTP 403 and one stderr line naming the origin. An optional pairing token adds a second check: it is off by default, and a server requires one only when started with `--token <token>` (or `--token auto`, which makes and prints one), `AUDIORECTIVE_MCP_TOKEN` or `PageBridge.listen({ token })`; the page then passes `connectMcpBridge(tools, url, { token })`, sent as a WebSocket subprotocol. A foreign page can no longer replace the paired page.
- **daw:** `mcpTools(workspace, { allow })` limits the agent to the categories `read`, `edit`, `export` and `operations` (default: all). Every `McpTool` has a `category`; tools outside `allow` are not listed, `run_operation` refuses operations the policy does not allow, and `read_project` lists only the operations the agent may call. `MCP_TOOL_CATEGORIES` and `McpToolCategory` are exported.
- **daw:** listen to selected tracks. `renderMixRange(workspace, { …, trackIds })` renders only those tracks, each through its own devices, instruments, inserts, volume, pan and automation, the bus it outputs to and the master, so the audio equals a live solo of the same tracks; send returns they feed are included, a muted track stays silent, and the measurements (`peakDbFS`, `loudnessLUFS`, `seams`) refer to their sum. An empty list or an unknown id throws `RangeError`. The MCP `listen` tool takes `trackIds`, and `audio: true` returns a short WAV as an MCP audio block when the app passes the new `mcpTools` option `listenAudio: { maxSeconds }` (default off; without it the call returns the numbers and an `audioNote`). `McpToolResult` has an optional `audio: { mimeType, base64 }`, and the `@audiorective/mcp` server forwards it as an audio content block.
- **daw:** MIDI controller lanes on a MIDI track. `ProjectTrack.controllerLanes` is a list of `ControllerLane` (`expression` `channelController`, `pitchBend`, `channelPressure`, `polyPressure` or `programChange`, `channel` 0 to 15, `controller`, `points` of `{ time` in project beats, `value` an integer (0 to 127; pitch bend 0 to 16383, centre 8192), `shape` `"linear"` or `"hold"` `}`), set with `Project.setControllerLane(trackId, lane)` (an empty `points` removes the lane; undoable, part of the version) and the `applyEdits` / MCP operation `setControllerLane`; `read_project` lists the lanes and `read_automation({ trackId, expression, channel, controller? })` returns one. A running Workspace plays them in Arrangement as MIDI messages to the track's first device or sampler: a message at each point and, along a linear segment, one at each 1/32 beat where the rounded value changes; a start, seek or loop wrap first sends the value in force there. `renderMixRange`, `renderStems` and `exportAudioFallbackTo` send the same messages, `exportMidiFile` writes them into the track, and `rippleDelete` and an inserting `copyRange` move them with the song. New types `ControllerLane`, `ControllerPoint`, `ControllerExpression` and `SetControllerLaneEdit` are exported.
- **daw:** `openDawProject` reads the controller movement Bitwig Studio writes (sustain, mod wheel, any controller, pitch bend; a `Points` with `unit="normalized"` beside the track's `Clips`, in absolute beats) into `track.controllerLanes` instead of keeping it unread; the lane is saved back in the form the file had (an unchanged lane keeps its XML, an edited one is written in the same place with the points it did not change kept as they were).
- **daw:** a `.dawproject` written by another DAW with audio stretched by warp markers (Bitwig Studio: `Clip > Clips > Clip > Warps` with `Audio algorithm="stretch"` and `Warp` points; audio of one tempo in a song of another) opens as an audio clip with `stretch = { ratio, source, anchors? }`: `source` is the window of the original file the markers cover, `ratio` is timeline seconds over audio seconds, and each place where the speed changes (a warp marker or a tempo change inside the clip) is an anchor. Its audio is a varispeed placeholder (exact length, pitch moved). New option `WorkspaceOptions.stretch` (a `WaveStretchProcessor`, e.g. `TimeStretch`; also in `workspace.open` options and `workspace.deviceOptions`): `openWorkspace`, `openWorkspaceBlob`, `Workspace.create` over an opened project and `workspace.open` render every such clip pitch-preserving before the song plays, as no Undo step and no version change; an engine failure leaves that clip on varispeed with a warning. Without `stretch` `workspace.warnings` says once per song how many clips play with a changed pitch. Any `algorithm` other than `stretch` is varispeed by intent and is not rendered. `workspace.open` and the open functions decode compressed or file-backed audio of such clips first; `openDawProject` alone leaves those clips in the file with a warning. `read_project` clips carry `stretchRatio`.
- **daw:** a time-stretched clip is saved in Bitwig's form: the original audio file (written once) with `Warps` and `algorithm="stretch"`, `Warp` points at the clip's ends, each anchor and each tempo change inside it, instead of the rendered WAV. An unchanged clip from a file keeps its XML; an edit rewrites only what changed. A tempo change after open keeps the clip's seconds and ratio and writes the `Warp` times in beats from the current tempo map.
- **daw:** a `.dawproject` written by another DAW opens with its compressed audio (Ogg Vorbis, Opus, MP3, FLAC, AAC, AIFF: whatever the browser decodes). `openDawProject` and `openDawProjectBlob` read such a clip as an ordinary audio clip with its place, length, file window, fades and gain, sized by the `sampleRate`, `channels` and `duration` of its `Audio` element, and its `clip.media` is pending decode: the new `AudioMedia.pending` is `true` and `readFrames` and `peaks` reject with `AudioMedia is not decoded yet: open the project with openWorkspace so the browser decodes "…".` `openWorkspace`, `openWorkspaceBlob` and `workspace.open` decode each such file with the context's `decodeAudioData`, resample it with core's `resamplePCM` to the Workspace's rate as `importAudioFiles` does, and open the clips as ordinary in-memory clips before the song starts, so the live engine and every offline render hear them. A file the browser cannot decode is named in `workspace.warnings` and its clips stay in the file unchanged and silent. A save writes every compressed file back with its original bytes and path (also for an edited clip), and the `Audio` element keeps the rate, channels and duration the file stated; `portabilityReport` lists the compressed files that travel unchanged. A PreSonus Studio One 7.0.2 export that read with no audio clips now reads 122 (the rest are stretched by warp markers and stay in the file). An MP3 without the encoder's gapless header plays its 1105-sample encoder delay late; one with it is exact. Opened through `Workspace.create` over an undecoded Project, the clips report the error in `cells.error` instead of playing.

### Changed

- **host:** `WebClapHost.saveState()` also refreshes `parameterInfo` and `params` from the plug-in before the bytes arrive (it asked for the state alone before), so a parameter the plug-in changed inside is current after a save.
- **mcp, daw:** the server refuses a handshake whose `Origin` is not allowed or missing; a non-browser client that sends no `Origin` needs `--allow-missing-origin` (`allowMissingOrigin`). `McpTool` gains a required `category`. A call for a tool the page does not serve answers `No tool named "…". This page serves: …`.
- **daw:** `Project.setVolumeAutomation` and the clip gain automation store the last point's `shape` as `"hold"` (nothing follows it, and a file cannot carry one), as controller lanes already did; `read_automation` and `track.volumeAutomation` show it so.
- **daw:** the constructor parameter `cleanup` of `AudioMedia` is `onDispose` (positional, so no call changes); `pnpm check:vocabulary` and `pnpm check:jsdoc` no longer have a `daw` baseline: every public `daw` member has a JSDoc line with its unit, range and edge behaviour.
- **daw:** `saveDawProject` writes the controller events of a MIDI clip (sustain, mod wheel, any controller, pitch bend, pressure, program) as `RealPoint` with `unit="normalized"` and `interpolation="hold"` (value `/ 127`, pitch bend `/ 16383`) instead of `IntegerPoint`, which Bitwig Studio ignores: before, a song's controller movement was missing after a trip through Bitwig. A file written before still opens (`IntegerPoint` is read as raw values).
- **daw:** a clip stretched in the app is saved in the standard form (the original audio with `Warps`) and also with its pitch-correct render in the file's own folder: `audiorective/render/<clip id>.wav` (float32 WAV) and a `render` record on the clip's entry in `audiorective/state.json` (the original file's path, the window in frames, the clip's frames, rate and channels, a hash of the window's samples, the ratio and the anchors). Reopening uses the render, with no placeholder, no engine call and no warning, only while that record still equals what the standard XML says (same file, window, length, hash and time map, to 1.5 frames); a file another DAW edited (a changed warp point or tempo) or saved without the folder (Bitwig drops it) ignores the render and opens as before (a render with `WorkspaceOptions.stretch`, otherwise varispeed and a warning). Pieces of a split and copies share one stored render. A clip that is only a varispeed placeholder stores no render; a clip a file stretched and an engine rendered on open stores its render, so the file reopens with that sound without an engine. A stretched clip adds its rendered audio to the file's size, and `portabilityReport` says the render stays in the Audiorective package.
- **daw:** `clip.stretch.source` is now a window of the original recording (`sourceOffset` and `sourceLength` describe it in the whole file) after a trim or a split, not its own recording. Files written before the Warps form (the rendered WAV as the clip, the original under `audiorective/source/`, the ratio in the details entry) still open with the render as playback; a stretched clip is saved with its render too, in the file's own folder (see the next entry), so reopening it needs no stretch engine.
- **daw:** `openDawProject` reads the audio clips Bitwig Studio writes (an outer `Clip` around a `Clips` with one inner `Clip` holding `Audio`, a `Lanes` with a gain `Points`, or `Warps`) as ordinary audio clips when the audio runs at its original speed: place, length, file window, fades, flat gain and name, with beats converted through the tempo map. `Warps` count as unstretched when audio seconds advance as timeline seconds do at the clip's start, end and every tempo change inside it, within 1.5 frames of the recording. Such a clip used to stay in the file with the warning "Audio clip with warps or nested clips". A clip that is stretched stays in the file and the warning says how much (`Audio clip stretched by warp markers (4.000 s of audio over 4.800 s of timeline)`), as does one with several nested clips, a moving gain curve or a repeating loop. Saving writes an edit (move, resize, trim, fades, gain, name, remove, duplicate, split) into the same nested form and touches only the changed values; a clip the form cannot say (a loop, a moving gain) is written in Audiorective's own form.
- **daw:** `openDawProject` opens a PreSonus Studio One 7.0.2 file. `<Project version="0.1">` is read as 1.0 with a warning (other versions still fail); HTML entities of a fixed table in `metadata.xml` (`&copy;`, `&mdash;`, ...) are read as characters and any other entity fails with `Project metadata.xml is invalid: ...` (it said `Project XML is invalid`); a `Note` without `channel` is read as channel 0 with a warning; a clip with a note at a negative `time`, volume automation with two points at one time and a clip without `duration` stay in the file, are not played, and are named in the warning (the first one was a hard error in a file from another application, the other two failed the whole open). New `pnpm --filter @audiorective/daw probe:studio-one` downloads the public export and prints what it reads.
- **daw:** a save with no edit leaves a file from another application with the same `project.xml` tree (elements, attributes, order), every other archive entry byte for byte, one added `audiorective/` sidecar entry, and `metadata.xml` written again with the same content; the docs no longer call this byte-identical.
- **daw:** renamed `RenderStemsOptions.tail` to `tailSeconds`, as in `renderSession` and `exportAudioFallbackTo`, and the MCP `export_stems` argument `tail` to `tailSeconds` (old → new). `renderStems` results gain `warnings: readonly string[]`, one sentence for each silent stem (muted track, or a MIDI track with no device and no `instruments` entry); `export_stems` repeats them in its result.
- **daw:** `daw/project` (and the root) now export the types that public signatures already named: `ProjectEditSongPart`, `ProjectMarker`, `AudioClipOptions`, `AudioClipBase` and `EffectSlot`; `daw/mcp` exports `OpSpec`. A test fails when an exported signature names a type no entry exports.
- **daw:** every public editing method of `Project` and `ProjectSession` now has an `applyEdits` operation, offered by the MCP `apply_edits` tool with its JSON Schema. New operation types (each is the method name): `splitClip`, `duplicateClip`, `removeClip`, `setClipLoop`, `addMidiClip`, `setAudioClipEnvelope`, `setAudioClipGainAutomation`, `setVolumeAutomation`, `addTrack`, `removeTrack`, `setTrackName`, `setTrackVolume`, `setTrackMuted`, `setTrackSolo`, `setTrackPan`, `setTrackRouting`, `setTrackEffects`, `setTrackRackPreset`, `setTrackMacroValue`, `setMasterVolume`, `setTitle`, `setTempoChanges`, `setTimeSignatureChanges`, `setMarkers`, `removeDevice`, `moveDevice`, `addScene`, `renameScene`, `moveScene`, `removeScene`, `duplicateScene`, `setMidiClip`, `moveSlotClip`, `clearSlot`, `copyToSlot` and `copyToArrangement`; `moveClip` also takes `trackId`. Positions are `atBeat` or `atSeconds`. `as` now names clips, tracks and scenes any operation makes, and `{ fromCopy }` selects them (also in `trackId` and `sceneId`), so one request can add a track, a clip on it and its notes. The receipt gains `createdTracks` and `createdScenes`, `copies[as][].from` is optional, and rejections gain the codes `track-not-found`, `scene-not-found` and `device-not-found`. Methods that need PCM, plug-in bytes or are not edits have no operation; `docs/mcp.md` lists each with its reason and a test fails when a new public method is in neither list. `read_project` now shows track volume, mute, solo, pan, output and sends, `masterVolume`, `devices`, `trackEffects`, `volumeAutomation`, `clipEnvelopes` and `clipGainAutomation`.
- **daw:** `project.edit` and `applyEdits` now record mixer changes as part of the Undo step: `setTitle`, `setMasterVolume`, `setTrackName`, `setTrackVolume`, `setTrackMuted`, `setTrackSolo`, `setTrackPan`, `setTrackRouting`, `setTrackEffects`, `setTrackRackPreset` and `setTrackMacroValue`. Undo returns `conflict` when a later change touched the same value. They used to throw `Project edit covers tracks, clips, notes, tempo, meter, markers, scenes, devices and volume automation only.`, which is gone.
- **daw:** renamed `applyEdits` operations (old → new): `renameClip` → `setClipName`; `setNoteVelocity` → `editNotes` with `notes: [{ id, velocity }]`. The type `RenameClipEdit` is `SetClipNameEdit` and `SetNoteVelocityEdit` is removed. `project.duplicateClip(clipId, time, trackId)` → `project.duplicateClip(clipId, time, { trackId })`.
- **daw:** a clip from another application's file whose standard gain curve moves (`Lanes > Audio + Points(expression="gain")`, linear values, `hold` or `linear` points in seconds or beats) opens as the clip's gain automation and plays it, where it used to stay out of the model and silent. The file's XML is untouched on save; editing the curve rewrites only its points in the file's own time unit. Pan and other expressions are still kept, not played.
- **daw:** a freshly written `.dawproject` states the arrangement in beats, as Bitwig does: audio `Clips`, `Markers` and volume automation use `timeUnit="beats"` converted through the tempo map (Bitwig converted seconds with the starting tempo, so audio clips and markers landed wrong under tempo changes), audio content stays in seconds (`contentTimeUnit="seconds"`), and clip fades are written with `fadeTimeUnit="beats"` (Bitwig reads fades as beats whatever the unit says), measured from the clip start (fade-in) and end (fade-out). Clip gain and its curve are also written as the standard `Lanes > Audio + Points(expression="gain")` that Bitwig shows as the clip's Gain (not for stretched or looped clips); Audiorective's own details stay the authority on reading, and a file without them reads a flat curve as the clip gain and keeps a clip with a moving curve unplayed. Reading converts beats back to seconds through the file's tempo map, exact to 1e-12 s, and tempo is read before the arrangement; audio clips, fades and volume automation in beats are now read (audio in a beats lane needs `contentTimeUnit="seconds"`). A file patched from another application keeps its source's unit. `portabilityReport` no longer warns about gain on plain clips.
- **daw:** live edits while playing are click-free in more cases. Splitting a clip under the playhead keeps the waveform continuous (the second half joins the crossfade at the level the seam is at). A track that changes between mono and stereo through a device change (a plug-in added to or removed from a mono track, including instrument sounds and buses) crosses between two ways into its channel strip, one per pan law, with gains scheduled ahead of time, so the level glides over the 25 ms crossfade and no graph edit is heard; the audio clock, not the wall clock, decides when a replaced plug-in or sampler is released. Moving a playing MIDI clip keeps the notes that still sound at the playhead. Clip edits cut 40 ms ahead (they were 25 ms), which removed a rare single-sample phase step under heavy CPU load. Offline renders are unchanged.
- **daw:** `importAudioFiles` resamples with core's `resamplePCM` (windowed sinc) instead of an `OfflineAudioContext`, which used linear interpolation and lost high frequencies; alignment and lengths are unchanged.
- **daw:** `openDawProject` and `openDawProjectBlob` keep, instead of rejecting, what the model has no field for. A file from another application (or any file with a folder track, a bare master `Channel`, Vst3/AU plug-ins, standard `Equalizer`/`Compressor` devices, tempo ramps, `TimeSignatureAutomation`, automation lanes other than track volume, warped or nested audio clips, a disabled clip, beat markers, `color`/`comment`, other `MetaData` fields, disabled or pre-fader sends, a `decibel` volume or a pan with `min`/`max`) opens, and the warnings name each kind under `Kept in the file unchanged, not played or edited: ...`. The next save writes only what the project changed since it was opened into the file's own XML (the other application's name, IDs, attributes, plug-in presets and unchanged clips come back as they were); a clip the model cannot play stays in the file and is silent. These used to throw (`Project XML has unsupported ... content.`, `Project has unsupported ...`). A change the file cannot take is refused on save: `Project tempo changes cannot be saved...`, `Project markers cannot be saved...`, `Project master volume cannot be saved...`, `Project scene slot holds content the model does not carry...`. A file with nothing extra, written by Audiorective, is written from the model as before. See `docs/dawproject-support.md` for the element-by-element table.
- **daw:** Saving into a file from another application takes the edits real Bitwig 5.3 files need. Tempo steps written as same-time point pairs read as steps (only a linear run between two different values is a ramp) and `setTempoChanges` writes them back in that style; beat markers read through the tempo map and `setMarkers` writes them back in beats, keeping their colour; a new track goes after the last other track instead of before a master that comes first; a WebCLAP device's changed state reaches the file's own state entry. `Project markers cannot be saved...` is gone. `importMidiFile` no longer throws on identical time signatures at one tick (the last one wins, as for tempos).
- **daw:** `project.setClipSourceRange` takes looped and time-stretched clips (it threw for both). On a looped clip the range becomes the loop and the point the clip starts from (`loop = { start, end }`, `sourceOffset = start`) and the clip keeps its `time`, `duration` and fades, so it fills the same stretch of the timeline and repeats the new part; a MIDI `start` must be `>= 0`. On a time-stretched audio clip the range is in seconds of the stored stretched audio (as `clipRecording` shows it), keeps `time` and the stretch, and can only narrow the clip. The `applyEdits` and MCP `setClipSourceRange` operation follow, and the error `Project setClipSourceRange needs a clip without time-stretch or loop.` is gone.
- **daw:** plug-in devices are part of `project.edit` history and are applied to a running `Workspace` without stopping playback. `addWebClapDevice`, `removeDevice`, `setDeviceState` and the new `moveDevice` inside `project.edit` are Undo steps; Undo and Redo restore the device list, its order and each device's saved state (the running plug-in's last state is kept for Redo). `workspace.addWebClapDevice` is one Undo step ("Add <name>") and no longer calls `sync()`: the new plug-in is loaded off to the side and spliced into that track's chain while the transport runs, the other tracks play on, and the edited track may glitch briefly. A device change is a light edit, so it no longer sets `cells.needsSync`; track additions, removals and kind changes still do. A MIDI track plays through its first device, and through its `instruments` entry again when its last device goes. The error text `Project edit covers clips, notes, tempo, markers and volume automation only.` now lists scenes and devices.
- **daw:** Undo and Redo of a device or scene step no longer overwrite later work. A device's saved state is restored only when that step changed it (`setDeviceState`) or added or removed the device, so undoing "add device B" keeps a tuned device A, and a running `Workspace` skips `loadState` for an empty state. Undoing a `moveScene` returns `conflict` when the scenes were reordered outside history since.
- **daw:** `workspace.addWebClapDevice` rejects with `Workspace device was removed before it finished loading.` when Undo or a removal took the device out while it loaded, and a failed rebuild removes only that device (as Undo when nothing was edited since, else as a new "Remove <name>" edit) instead of undoing the latest edit.
- **daw:** a write through a Project-owned `clip.midi` (`edit` or `setNotes`) during a `readOnly` operation throws `Operation "…" is read-only and cannot change the project.` before the notes change; it used to throw only after the edit had run.
- **daw:** operation input and `applyEdits` operations reject unknown fields. `project.operations.call` (and MCP `run_operation`) throws `Operation "…": args has unknown field "…"; allowed: …` for a field an object schema with `properties` does not list, unless the schema sets `additionalProperties: true` (a behaviour change: extras used to pass silently); `applyEdits` rejects an unknown field on an operation, `clip` selector, range, position or note with `invalid-operation`. MCP: `read_project` lists each operation's `input` schema, `run_operation` returns `undoLabel` and quotes the schema when args are wrong, and `apply_edits`/`run_operation` return `status: "noop"` when the project did not change.
- **daw:** `resizeClip` and `splitClip` are non-destructive for MIDI clips (a behaviour change). Notes outside a clip's window are no longer deleted or cut: `resizeClip` moves `time` and the new `sourceOffset` together on a start edge and `duration` on the end edge, so extending an edge back reveals the same notes; `splitClip` makes two independent clips that each keep all the notes. Notes crossing a window edge are shortened at playback only. Extending a clip's start past its first note moves `sourceOffset` below 0 instead of shifting the notes later. Linked MIDI clips keep their own `time`, `duration`, `sourceOffset` and loop over the shared notes, so moving a start edge or setting a source range no longer needs `makeClipUnique`. A Session slot plays one stretch of the content on every pass (the clip's window, or for a looped clip the loop alone), where a loop that started after beat 0 used to replay the notes before it; `renderSession` renders the same stretch. `resizeClip` and `setClipSourceRange` keep the clip's `midi` object.

- **daw:** the `setTrackVolume` and `setMasterVolume` operations take `volume` (they took `value`), like `setTrackPan` takes `pan` and `setTrackMuted` takes `muted`; the parameter of `Project.setTrackVolume`, `Project.setMasterVolume` and the same `Workspace` methods is `volume`. `setTrackMacroValue` keeps `value`. An operation that still sends `value` is rejected with the allowed fields.
- **daw:** Undo and Redo of a mixer edit compare and restore only the values that edit changed. An edit that set a track's volume no longer conflicts with a later mute, macro change or insert change on the same track, and undoing it leaves that later change in place; a later change to the same value (the same key of the same track, the title or the master level) is still a `conflict`.
- **daw:** `applyEdits` checks every timeline clip a request created for overlap on the final arrangement, as it did for moved clips: `duplicateClip`, `addMidiClip`, `copyToArrangement` and the pieces `copyRange` makes are rejected with `code: "overlap"` when they end on another clip (audio positions that round to a frame are not an overlap). `rippleDelete` still overlaps the pieces it joins for its crossfade. Direct `Project` calls are unchanged.
- **daw:** the `applied` receipt of `applyEdits`, `undo` and `redo` gains `changedTracks` (tracks whose name, level, mute, solo, pan, inserts, macros, routing, devices or level automation changed), `removedTracks`, `changedScenes`, `removedScenes` and `song` (any of `"tempo"`, `"timeSignature"`, `"markers"`, `"title"`, `"masterVolume"`); they are empty arrays when nothing of that kind changed. The MCP `apply_edits` result carries them.
- **daw:** a position in an `applyEdits` operation (`splitClip`, `duplicateClip`, `copyToArrangement`, a `setMarkers` marker, a `setVolumeAutomation` point) may give both `atBeat` and `atSeconds` when they name the same moment at the tempo map as it is at that step (within 1e-6 s); they used to be rejected as "exactly one". Values that disagree are rejected with a `disagree` reason. `setTempoChanges`, `setTimeSignatureChanges`, `setMarkers`, `setVolumeAutomation`, `setTrackEffects` and `setTrackRouting` do nothing, and make no Undo step, when the list they get equals the current one.
- **daw:** MCP `read_project` rows go back into the replace-the-list operations unchanged. `volumeAutomation` and `clipGainAutomation` are one entry per track or clip, `{ trackId | clipId, points }`, with `atBeat`, `atSeconds`, `value` and `shape` at full precision; a curve of more than 32 points is `{ trackId | clipId, count, first, last }` (positions only). `markers` are `{ name, atBeat, atSeconds }`, `signatureChanges` are `{ beat, numerator, denominator }`, and `routing` is a new list of `{ trackId, routing: { outputBusId, sends } }` for tracks that do not output to the master unrouted (the track rows no longer carry `sends`). New MCP tool `read_automation` (`{ trackId }` or `{ clipId }`, optional `range`) returns a curve's points in the same row shape.
- **daw:** the MCP `apply_edits` input schema is compact: `ops.items` is `{ type }` with the operation names as an enum, and the tool description lists each operation as `name{fields}: summary` plus the field shapes; the tool list went from about 13,300 to about 4,900 tokens. Every field is still checked when the operation runs, and an unknown or malformed field is rejected with the allowed fields.
- **daw:** a note played live from a Session MIDI clip uses the level its MIDI byte gives (`round(velocity * 127) / 127`), the same as the Arrangement and `renderSession`, instead of the raw velocity: a 0.8 note plays 0.8031 in all of them, so a live Session and its offline render match to 1e-6.

- **effects:** the `Compressor` and `Limiter` option `lookahead` is `lookAhead`, the name a clock's look-ahead window already has (old → new; seconds as before). See `docs/vocabulary.md` for the name and unit each concept has across packages.
- **all packages:** `pnpm check:jsdoc`, `pnpm check:single-entry` and `pnpm check:vocabulary` run in `pnpm test`: every public class member and exported function or const has a JSDoc comment, each exported name comes from one entry per package, and no declaration uses a name the vocabulary disallows. The JSDoc of `core`, `clock`, `effects`, `launcher`, `host`, `mcp` and `widgets` gained the missing units, ranges and defaults.

### Fixed

- **effects, launcher:** values an audio node cannot take are refused before they are stored. `Filter` `type` outside `BiquadFilterType` still throws `Effect: invalid filter type "…".` but the param now keeps the type the filter plays; `Phaser` `baseFrequency` and `octaves` that give no finite sweep (NaN, Infinity) throw `RangeError` and keep their value, where before the param held the bad value and a later write of the other one used it; `PitchShift` `pitch` NaN throws `RangeError` and keeps its value. A `ClipLauncher` clip's `gainDb` (NaN, +Infinity; -Infinity still mutes) and `pitch` (NaN, infinite rate) throw `RangeError` and are not stored; before, a NaN `pitch` written while the clip played left the playing instance broken, so every later `pitch` write threw.
- **daw:** Undo of a built-in effect parameter set with `setDeviceParameter` is recorded per parameter (like a WebCLAP parameter): another parameter of the same track's rack that changed since no longer makes the Undo a conflict, and Undo puts back only the parameter it set. A whole-rack `setTrackEffects` still records the whole rack.
- **daw:** `ClapPlugin` `Parameters` from another application are read by their `unit`: `normalized` rows (a 0..1 fraction) are mapped into the plug-in's real range when it loads (`DeviceParameterRecord.normalized` marks the fraction until then), `linear` or no unit is the plug-in's own value, and any other unit skips the row with one warning so the plug-in's saved state sets it.
- **daw:** `listen` with `audio: true` needs the `export` permission as well as the `listenAudio` option, because audio leaves the page like an export; with `allow: ["read"]` it returns the numbers and an `audioNote` saying so. `mcpTools` throws when `listenAudio.maxSeconds` is not a finite number above 0.
- **daw:** the `setDeviceParameter` operation compares `expectedValue` within a relative 1e-6 (absolute 1e-9 near 0), so a float32 value printed and copied back is not a conflict.
- **daw:** `openDawProjectBlob` and `openWorkspace(context, file)` open a project whose plug-in state (or any other entry that is not audio, XML or JSON) is larger than 8 MiB: such entries get the limits of the bytes reader (128 MiB each, 512 MiB together); XML and JSON entries stay at 8 MiB each and 32 MiB together.
- **mcp:** a plain HTTP request to the bridge gets `426 Upgrade Required` with `Connection: close` and a one-line body instead of waiting.
- **host:** a WebCLAP plug-in's own change of a parameter while the host ramps it (automation, the GUI) ends the ramp and is reported, instead of being dropped.
- **daw:** a stop, pause or seek no longer leaves a sustain pedal, pitch bend or other controller where playback moved it: the Workspace sends the pedal up, the bend at centre and every other controller it moved back to its rest value (`controllerRestValue`: 8192 for bend, 100 for volume, 64 for pan, 127 for expression, 0 otherwise) to the track's device. A start or seek before a lane's first point sends the rest value instead of nothing, live and in `renderMixRange`, `renderStems` and the audio fallback.
- **daw:** a controller lane sorts its points before it makes the last one `"hold"` (`setControllerLane` and the operation); an out-of-order list used to lose the shape of the point that was last in time.
- **daw:** `read_project` and `read_automation` leave out `controller` for pitch bend, channel pressure and program lanes (it has no meaning there), so a lane read back can be sent to `setControllerLane` unchanged.
- **daw:** `rippleDelete` and an inserting `copyRange` keep a lane's ramps: the point they add carries the shape of the segment in force there, so values outside the range are unchanged.
- **daw:** at one time a track's messages play in this order, live, offline and in `exportMidiFile`: note-offs, program changes, controllers and bend, note-ons. A track lane replaces the clips' own events for the same expression, channel and controller (Bitwig Studio's rule) in Arrangement playback, offline renders and `exportMidiFile`; Session clips keep their own.
- **daw:** Undo of a controller lane edit is recorded lane by lane: a later change to another lane of the track no longer blocks it, a later change to the same lane still does.
- **daw:** `workspace.open(project)` applies edits made to the passed `Project` while it loaded (light edits at once, a new or removed track sets `cells.needsSync`); they used to count as applied. A rejected `open` leaves the caller's `Project` alone even with `ownsProject: true`, and a track added during the load no longer throws at the swap.
- **daw:** the `instruments` sampler plays the sustain pedal (CC64, one pedal for all channels); it ignores bend, mod wheel and other controllers, pressure and program change. `changedScenes` is documented as the scenes renamed or moved in the order. `workspace.auditionAudioClip(clipId)` finds a clip in a Session slot.
- **daw:** a `.dawproject` point's `interpolation` is how the value arrives at that point from the previous one (Bitwig Studio 6.1.7 reads it so; checked on track volume, clip gain and controller lanes). Volume automation and clip gain curves were written and read with the opposite meaning, so a curve that mixes `hold` and `linear` points came out shifted by one point in Bitwig. The codec now converts between the file's arrival meaning and the model's `shape` (how a point leaves toward the next) in both directions, and the tempo reader tells a ramp from a step by the point the value arrives at. A file an earlier build of this package saved gave `interpolation` the opposite (leaving) meaning for volume automation and clip gain curves; it still opens with the curves it was saved with: `audiorective/state.json` is now `version: 4`, a file whose `Application` is Audiorective and whose sidecar is older than 4 is read with the leaving meaning and converted, and the next save writes the arriving meaning and version 4. A file without the sidecar, from another application, or with version 4 is read with the arriving meaning.
- **daw:** a moving clip gain curve Bitwig Studio writes inside a nested audio clip (outer `Clip` > `Clips` > inner `Clip` > `Lanes` with the `Audio` and `Points` with `expression="gain"`) is read into the clip's `gainAutomation` (source seconds; beats run at the tempo where the clip starts; a curve without `timeUnit` is in the file's timeline unit, as Bitwig writes it) and plays; before, the clip stayed in the file unplayed with the warning "Audio clip with a moving gain curve inside a nested clip". An edit rewrites that clip's `Points` in the nested form, keeps the points it did not change and states `timeUnit` on the curve (Bitwig reads a curve without one in seconds); an unchanged save leaves the XML as it was. A trimmed or stretched nested clip with a moving curve stays in the file.
- **daw:** a hold written as a repeated value (Bitwig Studio writes `(0, 0.2) (8, 0.2) (8, 0.8)` for 0.2 held until 8, then 0.8) reads as a hold in track volume automation, which used to be kept in the file untouched, and in a clip gain curve, which used to turn into a ramp. A step after a ramp or at the first point is still kept in the file.
- **daw:** `openDawProject` no longer fails with `Project MIDI has unsupported control automation.` for a MIDI clip whose controller `Points` use `RealPoint`, another unit or another expression: the clip opens (`RealPoint` is read as normalized values, a linear segment is sampled into events every 1/32 beat) and a `Points` the model cannot read stays in the file with a warning.
- **daw:** `openDawProject` and `openDawProjectBlob` open an archive whose entry names are not ASCII (a WAV named in Chinese, `Übung.txt`); they were refused as "incomplete or corrupt" because the local header's name length (UTF-8 bytes) was compared with the name's length in UTF-16 units. Names without the UTF-8 flag (general purpose bit 11) are read as UTF-8 when they are valid UTF-8, else as code page 437; names `saveDawProjectTo` and `exportAudioFallbackTo` write carry the flag.
- **daw:** `rippleDelete` and an inserting `copyRange` move the content a kept file holds (a clip the model cannot play, a `Points` lane of a parameter it does not model) with the rest of the song, by the range's beats in a beats lane and its seconds in a seconds lane, instead of leaving it behind. Content they cannot trim, copy or split is refused: `Project ripple delete is blocked by kept content: …` or `Project copyRange is blocked by kept content: …` names the clip or lane, and nothing changes.
- **daw:** opening an archive is bounded before the memory is spent, and every entry is held to the size its directory declares while it inflates (`Project archive entry is larger than its directory declares: …`). `openDawProject` unpacks at most 128 MiB per entry and 512 MiB in all from a file of at most 128 MiB; `openDawProjectBlob` keeps audio entries on disk and caps the other entries at 8 MiB each and 32 MiB in all (8 GiB of archive). Both refuse a directory of more than 10,000 entries with `Project archive is too large.`, and both read zip64 archives.
- **daw:** opening one Blob in two `Workspace`s at once (for example at 44.1 and 48 kHz) gives each its own decoded audio; the compressed files are decoded for each context and neither sees the other's rate.
- **daw:** a compressed audio file (MP3, AAC) may decode up to 2048 frames short of the end a clip's window asks for (decoders drop priming frames and pad the last block); the clip still opens and plays the frames the file has, instead of failing the window check.
- **daw:** a stretched clip's ratio no longer drifts with every open and save. A clip stretched over one speed keeps the warp's own ratio, not the quotient of its rounded frame counts, and a warp whose slope differs from 1 by less than 1e-5 per second (a short clip is judged by its slope too) is the identity and is read as an unstretched clip.
- **daw:** a stretched clip whose original WAV is file-backed stays file-backed: `openDawProjectBlob` reads only the window the stretch plays into memory, and the original stays on disk.
- **host, daw:** a WebCLAP parameter change no longer clicks. While the context runs, `WebClapHost` moves a smooth parameter (continuous, or stepped with at least 128 values, and not an enum) to its new value over 20 ms as value events 32 frames apart, on the parameter's own grid, instead of one event; a plug-in without smoothing of its own stepped its sound (worst sample step 0.0141 against 0.0018 steady for `amp gain` 68 to 20 on the test synth, now 0.0012). `project.setDeviceParameter`, Undo and Redo take this path; an enum, a short stepped parameter, a loaded state and a context that is not running (an offline render) take the value at once. Events in one block reach the plug-in in time order.
- **daw:** a Session clip sends its controllers, pitch bend, program changes and pressure as the Arrangement does for the same content: the values before the clip's window (its loop, for a looped clip) are carried to the start of every pass, a pedal still down at a pass end is released there, and each controller a clip moved goes back to rest when the clip stops, is replaced, or the transport stops, pauses or seeks, unless a later clip took it over. Session clips used to send notes only.
- **midi, daw:** one rest-value rule. `@audiorective/midi` exports `controllerRestValue(expression, controller)` and `controllerRestOf(data)` (the message that puts a controller back); the DAW uses them for lanes, Session clips and the stop-and-seek release, and `daw/project` re-exports `controllerRestValue`. `ControllerExpression`-shaped input is `RestExpression` in the midi package.

### Fixed

- **daw:** a linked MIDI clip is written without an `id` on its `Clip`, so the saved `project.xml` validates against the official schema (an `id` there made it invalid). Its identity travels in the private details; a file written with the `id` still opens, and that clip gets a new ID.
- **daw:** editing while playing no longer clicks or drops sound. A live clip edit (move, trim, split, source range, delete) now crossfades: the audio it replaces fades out over 12 ms from a shared cut time and the new source starts there at the same place in the clip with a matching fade-in, where it used to cut hard and restart at a phase that could be off by several milliseconds. A clip trimmed to or before the playhead fades out over the same 12 ms instead of stopping hard, and a seek while playing crossfades from the old position to the new (a stopped seek and offline renders are unchanged; the new material is sample-accurate once the 12 ms fade-in has passed). Adding, removing or moving a device on a playing track wires the new chain behind its own gate and crossfades from the old chain over 25 ms, disposing the old devices after the fade, where it used to rewire in one hard step. Offline renders are unchanged. Editing a MIDI clip's notes while it plays ends only the sounding notes the edit moved, re-pitched, shortened past now or removed; a held note the edit did not touch keeps sounding (the edit used to silence every held note of the track). A held note whose pitch, start or length is edited so that it still covers the playhead ends the old pitch and sounds the new one at once, with the same velocity, until the note's end (it used to stay silent until its original end). Repeated clip edits faster than the 12 ms fade (a 60 Hz drag, ten moves in 50 ms) no longer click: a source that is cut while still fading in or out continues from its own level, and a replacement source starts silent so that its first sample cannot leak ahead of the fade. Switching Session scenes whose clips hold the same pitch no longer silences the new note: a clip's note-off now releases only voices that started at or before its own note-on.
- **midi:** `Instrument.noteOff(note, when?, since?)` takes the start time of the note-on it answers, and `MidiClip` passes it. An instrument that tracks voices (the Workspace's sampler sink) releases only voices that began at or before `since`; an instrument that ignores the argument behaves as before.
- **core:** a smoothed write to a `SchedulableParam` bound to an `AudioParam` (the default 10 ms ramp) is no longer overwritten by the rAF readback of the not-yet-ramped native value, which made displays such as the EQ curve jump back to the old value for about 100 ms.
- **mcp, daw:** two pages no longer flap. The server closes a replaced page with WebSocket code `4000` (`replaced by another page`); `connectMcpBridge` does not reconnect on it, calls the new `onReplaced` option and stays closed until the new `bridge.connect()`. A `WebSocket` constructor that throws is reported through `onStatus(false)` and retried; a non-string `error` in a page frame fails the call with its message; `tools/list` fails with the page's error instead of returning an empty list.
- **daw/mcp:** `read_project` and `find` report `sourceOffset`, `sourceLength` (audio) and `loopStart`/`loopEnd` for timeline and Session clips, and `apply_edits` lists `resizeClip` and `setClipSourceRange` with their units.
- **daw/dawproject:** a seconds-unit MIDI clip with a negative `playStart` (or content before time 0) opens instead of throwing `Project time needs finite non-negative seconds.`; the first tempo continues before project second 0.
- **daw:** a sustain pedal still down at a MIDI window or loop pass end is released there (playback only) even when no later event follows, and so at a clip's natural end too.
- **daw:** `workspace.auditionAudioClip` no longer skips the first render quanta of a clip: it starts after the clip's buffer is ready (in-memory) or from a fresh origin (file-backed) instead of a start time taken before preparation.
- **midi, daw:** abutting notes whose `start + duration` differs from the next `start` by float round-off (triplets, 0.1-beat grids) no longer drop the next note in live playback: a `MidiClip` and the `Sampler` instrument treat times within 1 ns as one instant.
- **midi:** a `MidiClip` in a launcher that is stopped and launched again plays its current notes in the first pass, not the notes from before an edit made since it stopped.
- **daw:** the Session's cross-track linked-clip note follower stops listening when its launcher is disposed or rebuilt.
- **midi, daw:** abutting same-pitch notes (each note ending exactly where the next starts) no longer go silent in live playback. A `MidiClip` on a clock or launcher now sends its messages in time order with a note-off before a note-on at the same time, and a `Sampler` instrument (`WorkspaceOptions.instruments`) ignores a note-off sent before a same-time note-on instead of cutting the new voice.
- **daw:** Opening a `.dawproject` with files this codec does not use keeps them and writes them back unchanged on save, instead of failing with `Project archive has unsupported files.`
- **launcher:** A launch waiting for `clock.start()` with no time now begins exactly on beat 0 instead of at the next timer tick.
- **launcher:** A scheduler clip stopped in the same look-ahead as a clock refresh (another track's launch, an edit, a tempo change) still cuts its held notes at the stop instead of letting them ring.
- **daw:** `workspace.deviceOptions` approves the bundle URLs the workspace has loaded, so a file saved from it opens again with its plug-ins; other URLs still need `resolveBundle`.
- **daw:** Live plug-in state capture is no longer on the public `Project` type; apps without a Workspace use `project.setDeviceState`.
- **widgets:** A widget mounted inside an effect keeps updating after that effect re-runs. A Delete handled by the piano roll no longer reaches the app's own key handlers.
- **daw:** `selectionFor` keeps pruning when first called inside an effect.
- **host:** A saved patch now loads on a context that is not rendering yet, so offline renders and exports work after a synth edit, and `params` reflect the loaded patch after the state settles.
- **host:** `saveState` hands parameter changes still queued for the audio thread to the plug-in first, so a value set right before a save is in the saved state.
- **daw:** Both project open paths validate ZIP completeness and entry CRCs. Unsupported master settings fail on open. Audio sidecar details follow clip identity, edited MIDI falls back to standard content with a warning, recorded MIDI channel messages round-trip, XML text is validated on entry, and generated IDs survive save and reopen without reusing deleted IDs. Disposed projects reject edits and saves.
- **daw:** Media read failures report once per clip per playback run in `workspace.cells.error`, retry at the next `play()` or `seek()`, clear on a successful read and abort audio fallback export. A `seek()` while playing keeps the transport `playing` while it waits for file-backed media, and `takeAnchor(audioTime)` maps that audio time to project time, so a take placed from an anchor taken right after `play()` is exact; an anchor captured while a seek waits for media throws at `takePosition`.

- **recorder:** A transport `start` cancels a pending `quantize` take (its boundary was planned on the previous anchor) with `AbortError`; a take armed with an explicit `when` still survives `start`.
- **daw:** A seek that waits for media gives attached schedulers a real seek before holding the transport `playing`, so an armed recorder take is cancelled as on any seek.
- **effects:** Channel mute and output gating transition smoothly during playback.

### Migration

- **daw:** MIDI clip windows. Existing projects and clips open with `sourceOffset` 0 and play as before, and a MIDI loop's `startBeat` and `endBeat` are unchanged (with `sourceOffset` 0 clip-local beats equal content beats). What changes is what edits do: code that relied on `resizeClip` or `splitClip` deleting or cutting MIDI notes now finds them still in `clip.midi.notes` (read the played notes with `clip.playbackEvents()`, or window them with `sourceOffset` and `duration`), and code that read a trimmed clip's note `start` as clip-local must subtract `clip.sourceOffset`. A start edge dragged left of the first note gives a negative `sourceOffset` instead of shifting the notes. Code that called `makeClipUnique` before moving the start edge of a linked clip can drop the call. Session slots that looped from beat 2 or later no longer replay the lead-in on each pass.
- **daw:** **Breaking.** `Project.trimClip` is removed; `resizeClip` takes absolute timeline edges instead of clip-local ones. Migration:

  | Before                                            | After                                                                                  |
  | ------------------------------------------------- | -------------------------------------------------------------------------------------- |
  | `project.trimClip(id, localStart, localEnd)`      | `project.resizeClip(id, { start: clip.time + localStart, end: clip.time + localEnd })` |
  | `project.trimClip(id, localStart, clip.duration)` | `project.resizeClip(id, { start: clip.time + localStart })`                            |

- **daw / daw-demo:** A project file's WebCLAP URL requires app approval. Supply `resolveBundle` when opening a project. The demo approves its built-in synth and bundles that the user explicitly loads in the current session.

- **daw:** **Breaking.** `workspace.session` no longer makes slot `i` of a track out of the track's `i`-th Arrangement clip; its slots are the Project's Session grid, `sessionFor(project)`. `session.value.tracks[trackId].clips[i]` is scene `i`'s slot clip (`null` when empty), `launchScene(i)` launches scene `i` and stops the tracks whose slot is empty, and `workspace.sessionClip(trackId, clipId)` finds a slot clip by its id (a timeline clip has none). Scenes added or removed change the launcher in place. Migration:

  | Before                                                                               | After                                                                                                                            |
  | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
  | `project.addMidiClip(track.id, data, time)` placed far away to give a Session slot   | `sessionFor(project).setMidiClip({ trackId: track.id, sceneId }, data)`                                                          |
  | `project.addAudioClip(track.id, audio, time)` placed far away to give a Session slot | `sessionFor(project).setAudioClip({ trackId: track.id, sceneId }, audio)`                                                        |
  | scene `i` = the `i`-th clip of every track                                           | `sessionFor(project).addScene({ name })`, once per scene, in order                                                               |
  | a clip on both the timeline and in the Session                                       | a slot clip and an Arrangement clip with the same content; `session.copyToArrangement(slot, { atBeat })` makes the timeline copy |
  | grid layout built from `track.clips` grouped by time                                 | `sessionFor(project).scenes` and `clipAt({ trackId, sceneId })`                                                                  |
  | a scene launch left tracks with nothing in that scene playing                        | `launchScene(i)` stops them; `launchScene([clipA, clipB])` still starts exactly those clips                                      |

### Documentation and evaluation

- **docs / skill:** clarify Clock transport states, empty processor registries, nullable launcher slots, file-backed clip media windows and fixed-tempo punch occurrence planning. These are existing APIs; runtime and persisted project formats are unchanged.
- **evals:** accept public widget delegation, current MIDI held cells and signal cleanup; separate actual reference-read evidence from answer prose and keep source preparation distinct from hand-written recording engines. Routing failures remain in per-run means and summary denominators as unmet; incomplete calls are reported separately. Historical frozen grades are retained. Required reference reads are enforced per solver run before grading; a missing route fails the run even when its API happens to be correct.

### Changed

- **widgets:** `attachClipGesture` moved to `@audiorective/widgets/clip`, the preferred import path; `@audiorective/widgets/arrangement` still re-exports it, so existing imports work. The widgets guide calls a range inside one file a "region", so "clip" always means a timeline clip.
- **widgets:** The piano roll velocity lane is easier to use: wider stems with round handles (fully visible at beat 0), the active note's bar on top and highlighted in a chord, a 1-127 value label while dragging, and ArrowUp/ArrowDown (Shift for 10) to nudge the active note through `onNoteEdit` `kind: "velocity"`.

Signature, ZIP layout, manifest, stems, cancellation, progress and errors are unchanged; the render waits between steps for file-backed media chunks, WebCLAP device messages and the OPFS writer, and the same project exports the same samples. The offline context holds one channel for the whole render in memory (about 11 MB per minute at 48 kHz); Chromium refuses a render above about 3.1 hours, which fails with the export's own error.
- **recorder:** a worklet `currentFrame` that repeats for one render quantum and then catches up no longer discards 128 captured frames or reports a false `dropouts` gap. A real forward skip is still reported and filled with silence.

### Fixed

- **core:** `disconnect(processor.input)` removes connections established using the processor owner and vice versa. `FilePlayer` preserves its initial or edited playback rate across media loads and source changes.
- **pads:** rebuilding a choke group preserves an already committed release envelope and its original retirement time, avoiding a gain jump or extended tail.

- **core / pads:** an observer error remains reported while context-wide parameter readback continues; owner effects, graph watchers and AutomationBinding survive consumer-effect reruns until explicitly disposed. Aborted engine setup releases subsequently registered processors and helper graphs. Pad commands do not track voice start state; FilePlayer source/Stop/dispose publish coherent inactive state.
- **effects:** Channel meter disposal is repeatable; effect readiness/error/buffer transitions are batched. Chain handovers wait for audio time across suspension. Rapid Distortion edits coalesce into a bounded pool of prebuilt silent arms with native gain handovers; they do not rewrite an audible curve or reserve caller-owned offline suspend points.
- **recorder / midi / host:** scheduling Stop cannot exempt an unstarted audio take from transport cancellation; MIDI start/end timers recheck audio time across suspension and record commands do not track tempo. Cancelling a future WebCLAP note-off retains its channels, while executed releases leave later note-on ownership intact.

- **clock:** detach retracts the registration's sounding and future owned events at the current audio time, preserving other schedulers; a retained detached window cannot register new events.
- **clock:** a slider write after `cancelAndHoldAtTime(now)` preserves an incoming tempo ramp's historical integral, including repeated writes at the same instant, so transport beat does not jump.
- **clock:** refresh invalidates event ownership without re-anchoring the transport, preventing accumulated rounding from showing the previous bar at a count-in boundary.
- **clock types:** `cycleGridPoints` accepts the minimal core `BeatTiming`, just as `gridPoints` does; custom schedulers can pass their supplied timing without a Timeline adapter.

- **clock docs:** seconds-based rulers report transport position: start/seek seeds from the chosen beat and BPM, playback advances real seconds, and pauses hold it. Type hints distinguish this from cumulative listening duration across seeks; runtime position behavior is unchanged.

- **clock:** a `refresh()` called from an owned event’s cancellation coalesces with the outer edit, preserving its first captured audio boundary even if the audio clock advances inside the callback.

- **core:** `withCancel(event, undo).cancel(time?)` forwards the optional audio-context cancellation boundary to the wrapped event instead of cancelling it immediately. Cancellation and undo still run at most once; documentation and clock-owned voice examples preserve the same boundary.

- **docs / skill:** the prepared audio-stretch example executes `apply()` through the app's synchronous undo history, matching the ownership guidance; warp-editor guidance routes to that example.

- **widgets:** waveform selection previews stay local until release, when the shared model receives one edit. Escape, pointer cancellation, capture loss, external owner replacement and detachment restore the committed range without writing a preview to the model.
- **widgets:** curve, overlay, warp and arrangement gestures cancel on Escape, pointer cancellation, capture loss, stale owner replacement and disposal. Rejected or throwing edit commands restore the authoritative source view. Disabled curve/warp tools yield hit testing, and a background double click is claimed once across tools.
- **widgets:** mixer keyed rows preserve focused extension controls and text selection during reorder, optional controls follow owner capability changes, and meter/extension resources clean up once without disposing borrowed owners. Detached editor observers stop updating after view removal.

- **core:** live latency-compensation changes warm a new delay route and crossfade instead of hard-rewiring or moving an audible delay read head. Initial wiring remains exact; steady branches align sample-for-sample after the short phase blend. `arrivalOf()` and snapshots describe the solved target during the handover. Graph disposal disconnects pending helper routes and cancels their cleanup timers.

- **effects:** `Ducker.cells.reduction` reports actual output attenuation after wet/dry and click-free bypass, instead of the wet arm's detector envelope. The worklet reports every 512 audio frames; a meter reads or subscribes directly, without masking bypass to zero. Loading and failure report the remaining dry gain (`-Infinity` for silence, `0` for full bypass), with polling and reports cleaned up on disposal.

- **recorder:** a source or automation wired only to `recorder.input` is processed from the start, armed or not (a silent pull path to the destination), so a take holds what played at that audio time. Before, it was pulled only once a take armed: in an offline render the oscillator phase or ramp started late and the take came back time-shifted with no error.
- **core:** `Sampler.noteOff` releases only the held voices of the note that start by `when`. A later `noteOff` no longer moves the stop of a voice an earlier `noteOff` released, and a `noteOff` does not release a voice scheduled after it.
- **core / pads:** `Sampler.cells.activeVoices` and `PadBank.cells.activeVoices` count only started voices: a voice scheduled for the future joins at its start time, where before it counted at scheduling, one look-ahead early. `voice.playing` is unchanged (true until the voice ends); read `voice.started` for whether it has begun.
- **recorder:** a take with `length` is exactly that many frames. The capture worklet now counts the length from its first captured frame and never opens before the planned start frame, so a boundary already in the past or a late-opening gate no longer yields extra frames (a 0.25 s take could be 12512 frames). A render quantum the browser repeats is skipped, so chunks stay contiguous instead of failing with `AudioRecorder lost captured frames.`
- **player:** a queued quantized `WavePlayer` start stays cancellable by the clock leaving the transport after a `seek()`.
- **recorder / player:** while attached to a Clock, stop, pause, seek or detach cancels any take (`AudioRecorder.record`) or start (`WavePlayer.play`) that is armed but not yet started, `when` as well as `quantize`. `record()` rejects with `AbortError` and `play()` resolves `null`; a running take or sounding playback continues. Before, only quantized ones were cancelled, so a `when` start recorded or played material that no longer belonged to its position.
- **core:** `Sampler.noteOff(note, when)` moves a voice's pending release earlier when `when` is earlier; a later `when` is still ignored. A `noteOff` at a voice's own start silences a voice that has not started.
- **midi:** a `MidiClip` in a `ClipLauncher` loops per the launcher clip's `loop` and `length` alone (the `MidiClip`'s own `loop` and `length` apply when attached to a clock directly), and sends each note-off in the window that contains it, so a cut sends no stray late note-off.
- **midi:** a `refresh()` (or any retract) that lands after a note's on time but before the next window no longer revokes the started note or sends a stray note-off: a `MidiClip` decides "started" from the audio clock now (a `ClipLauncher`'s handle gains `now()`). `MidiKeyboard.press` on a pitch the sustain pedal alone is holding releases the old note at the re-strike, so the pitch keeps one voice.
- **midi:** when a retract revokes a not-yet-started note and the instrument's `noteOn` returned a cancellable event, `MidiClip` cancels it and sends no note-off; an instrument without one (a `Sampler`) still gets the note-off at the note's start time.
- **clock:** `gridPoints` takes a `BeatTiming`, so a scheduler can pass the `timing` its `schedule(window, timing)` receives.

- **blocks:** `StepSequencer` `transform` is beat-aware. `Hit` (what `transform` receives and returns, and what `onHit`, the `hit` event and a sound get) gains `beat` (absolute beat after offset, swing and repeat) and `durationBeats`. After `transform`, a changed `beat` or `durationBeats` is mapped through the transport's timing, so the hit stays on the grid under tempo automation (`beat: hit.beat + 0.125` is always a 32nd late); a hit that changes neither keeps the returned `when` and `duration`, as before, for millisecond nudges. If both `beat` and `when` changed, the hit sounds at `beatToTime(beat)` plus the `when` delta, and `duration` gets its delta added to the beat-derived length. A non-finite `beat` or a `durationBeats` not above 0 throws `Event transform "transform" ...`. A transform that shifts only `when` by a fixed amount is not tempo-locked.
- **widgets:** the step grid plugin context's lanes include the writable `pattern`, `rate`, `swing`, `direction`, `mute`, `solo` and `length` members of the real `Lane`.
- **docs:** swing is described once everywhere (every odd step delayed by `swing` of half a step, a fixed beat offset), and the sequencer docs say to `clock.refresh()` after changing state a `transform` reads.

- **blocks:** `StepSequencer` randomness is a pure function of a step's position. Before, `chance` and `context.random` drew from one stateful source, so any re-queue (an edit through `refreshOnEdit`, `clock.refresh()`, a seek) redrew every pending step: a chance step could flip between sounding and silent and humanize jitter jumped, and offline renders with different tick sizes differed. Now the chance draw is keyed by `seed`, lane, loop and step counter, and `context.randomFor` by the hit's lane, loop, step counter and repeat index, so the same step gets the same numbers in every window. Pass `options.random` to keep the old sequential source (the old instability comes with it).

## [2.3.2] - 2026-09-16

### Fixed

- **core:** `AudioEngine`'s state mirror only followed a `running → suspended`
  transition it caused itself, so a raw `context.resume()`/`context.suspend()`
  or Safari's `interrupted` state left `engine.core.state()` stale, and
  `start()`/`suspend()`/`resume()` guarded on that stale mirror instead of the
  real `context.state`. The engine now mirrors every `statechange` (including
  `interrupted` as `"suspended"` and `closed` as `"destroyed"`), and
  `start()`/`resume()` decide from the real context state, so either is
  idempotent even after an external change. (#36)
- **core:** `AudioEngine.destroy()` skipped disposing graphs, processors, and
  effects if the context had already been closed externally (the engine's
  own state mirror follows that closure to `"destroyed"`, and `destroy()`
  used to guard on the same signal). Cleanup completion is now tracked
  separately from the reactive state, so `destroy()` still runs it.

  preset.
- **effects:** `Channel` — gain → pan → mute strip with post-mute
  `send(bus, name, gain?)` into a `SendBus`; `gain` is linear.
- **effects:** `SendBus` — instance-scoped named receive points a `Channel`
  sends into.
- **effects:** `registerWorklet(ctx, name, source)` — exported so an app can
  pre-warm a worklet module ahead of first use.
- **effects:** `dbToGain(db)` / `gainToDb(gain)` — dB/linear-gain conversion
  helpers for the package's linear gain params.
- **effects:** `Effect` base class exported as the extension point for custom effects.
- **apps:** FX Rack showroom demo — a live effects processor and offline
  export engine built on `@audiorective/effects`: five inserts, two sends,
  compression, and a limiter, sharing one headless `FxRack` class between the
  live UI and the WAV export.

### Changed

- **apps:** the Latency Lab demo is folded into the Step Sequencer: the
  sequencer's `DrumMachine` now feeds the split/limiter/dry `defineGraph`
  (PDC toggle, bypass-by-edge-removal, the runtime-adjustable
  `LookaheadLimiter`, and the graph diagram all live on `/showroom/sequencer`),
  and the step highlight reads the pattern ruler at the time the listener is
  hearing — the render clock minus `engine.latency` and the output latency —
  instead of at `ctx.currentTime`. `DrumMachine` accepts a `tickSource`, so
  the whole machine renders offline through `renderTimeline`; the standalone
  `/showroom/latency-lab` page, its `Beat`/`Click` sources, and its flash row
  are gone.
- **core:** `AudioProcessor.context` widens from `AudioContext` to
  `BaseAudioContext`, so processors can be constructed against an
  `OfflineAudioContext` for offline measurement. Existing code that passes
  `proc.context` where an `AudioContext` is expected needs its own
  `AudioContext` reference, or a cast, at that call site.
- **core:** `Sampler` and `BufferPlayer` constructors widen their `ctx`
  parameter from `AudioContext` to `BaseAudioContext` — neither uses any
  `AudioContext`-only member, so both now build against an
  `OfflineAudioContext` too.

### Fixed

- **core:** an engine-owned graph that stops reaching `ctx.destination` (an
  edge condition turns false, the graph is disposed) drops its contribution
  to `engine.core.latency` instead of leaving the last value it solved.
- **core:** `getPathLatency` now always throws `LatencyUnknownError` for a
  processor that isn't part of the current solve — one dropped from the edge
  list, one whose owning graph was disposed, or one that only feeds an
  `AudioParam` — instead of leaking `defineGraph`'s internal "not present in
  the last solve" error for the first two cases.
- **core:** a processor wired into more than one live graph no longer loses
  `getPathLatency` when one of those graphs disposes or drops it — the
  internal graph registry now keeps one registration per graph a processor
  belongs to (instead of a single entry the most recently solved graph
  overwrote), so `getPathLatency` keeps resolving through whichever
  registration is still live.
- **core:** `AudioEngine` no longer leaks a dead graph handle on every
  dispose-and-rebuild (e.g. each `setPdc` toggle in the Latency Lab demo) —
  a disposed handle now removes itself from the engine's internal graph
  list, and `destroy()` iterates a copy of that list since each `dispose()`
  mutates it mid-loop.
- **devtools:** `measureLatency` destroys each per-sample-rate processor it
  builds after rendering, instead of leaking one `OfflineAudioContext`-scoped
  processor per configured rate.
- **core:** `getPathLatency` no longer fabricates a latency for a processor
  sitting in a disconnected component of the same graph (e.g. a branch that
  feeds nothing reaching the destination, while another branch of the same
  graph does) — it now throws `LatencyUnknownError` for that case instead of
  subtracting two unrelated solved arrivals. `GraphHandle` gains
  `reaches(from, to)` to answer the reachability check.

## [2.1.2] - 2026-08-24

### Added

- **core:** `EngineEnvironmentError` — thrown by the `AudioEngine` constructor
  (and therefore by `createEngine`) when the environment has no `AudioContext`
  constructor, instead of a bare `ReferenceError: AudioContext is not defined`.
  The message names the fix for the environment it landed in: on a server or
  build-time render it points at the client-only boundary
  (`next/dynamic` with `ssr: false`, Astro `client:only`); in a DOM without Web
  Audio (jsdom) it points at passing a context. Supplying one —
  `createEngine(setup, { context })` or `new AudioEngine(ctx)` — never triggers
  it, and the check runs before `setup`, so a failed call leaves no half-built
  graph.

### Changed

- **docs, skill:** audiorective is documented as officially client-only. New
  guide "Server-rendered frameworks" (`docs/client-boundary.md`) covers the
  boundary pattern for Next.js/Remix/Astro, why `'use client'` is not a
  boundary, how to choose the seam, and troubleshooting. The agent skill gained
  a matching top-level rule.

## [2.1.1] - 2026-08-15

### Fixed

- **clock, react, threejs, playcanvas:** these packages declared an exact
  version of `@audiorective/core` (`"2.1.0"` rather than `"^2.1.0"`), so a
  project on a newer core got a second copy of it nested under the binding
  package instead of sharing one. Two copies break `instanceof AudioProcessor`
  inside `AudioEngine` for processors built from the other copy, and give a
  single `AudioContext` two `ParamSync` loops. Upgrading any one binding
  package to 2.1.1 is enough to deduplicate it.

## [2.1.0] - 2026-08-15

### Added

- **clock:** New package `@audiorective/clock` — the timing and scheduling
  engine. `Clock` (worker-based look-ahead tick loop, transport
  start/pause/resume/stop/seek, miss detection via `onMiss`) + `Timeline`
  (beat↔time conversion, anchor, `generation`) + a standalone event-list
  `TempoParam` (V1: steps only; ramp methods throw, reserved for V2) + four
  stateless rulers (`LinearBarRuler`, `CycleBarRuler`, `LinearTimeRuler`,
  `CycleTimeRuler`) with grid iteration, `spans`, and a reactive `current`
  reading for visuals. Looping is expressed as a `CycleBarRuler` reading, not
  transport state — the beat axis never jumps. Linear and cycling rulers yield
  different grid points: linear counts forever (`index`), while a cycle ruler
  folds into its region (`step`, `cycle`) so a pattern's length can be passed
  as the division and `step` indexes it directly. See `docs/clock.md` and
  `docs/superpowers/specs/2026-07-04-clock-design.md`.
- **docs/skill:** `clock.md` — usage guide for the new package; `SKILL.md`
  packages table and read-next table updated accordingly.
- **apps:** `step-sequencer` — a 4-track × 16-step drum machine demoing the
  clock end to end: one `grid(patternLength)` loop over a cycle ruler whose
  region holds exactly one pass of the pattern (so scheduling needs no modulo),
  two rulers stacked on one timeline (`pattern` for scheduling and the
  playhead, `bar` for the absolute position readout), live tempo, transport,
  and live pattern editing, over a headless `DrumMachine` core that is an
  `AudioProcessor` consuming a `Clock`.

### Fixed

- **clock:** `Timeline.addRuler` stored the reading `Param` where the slot
  object belonged, so `timeline.rulers.<key>.current` was `undefined` at
  runtime (an `as unknown as` cast hid it from the type checker). Anything
  binding a UI to a ruler reading would have crashed on mount.
- **clock:** the published `.d.ts` degraded every consumer's ruler readings to
  `unknown` — a method generic named `K` collided with the `[K in keyof
TRulers]` mapped types and the declaration bundler emitted `TRulers[K$1]`.
  Source-level types were always correct, so only a consumer compiling against
  the built package saw it.

## [2.0.0]

### Changed

- **BREAKING — core:** Player taxonomy renamed to split cleanly on source
  (in-memory buffer vs streamed file) and voice model (polyphonic vs single
  playhead). `SoundPlayer` → `Sampler`, `StreamPlayer` → `FilePlayer` (and their
  `SoundPlayerOptions`/`StreamPlayerOptions` types → `SamplerOptions`/
  `FilePlayerOptions`). Update imports accordingly.

### Added

- **core:** `BufferPlayer` (+ `BufferPlayerOptions`) — buffer-backed
  single-playhead deck: sample-accurate `start`/`stop`/`loop` with a schedulable
  `params.rate` for beat-locked loops, stems, and DJ pitch/tempo moves. Its
  source is one-shot, so each `start()` builds a fresh node and re-points the
  stable `params.rate` at it via `SchedulableParam.rebind()`.
- **core:** `SchedulableParam.rebind()` — re-point a stable param at a freshly
  built source node, so a single reactive reference survives node rebuilds while
  scheduled automation always lands on the live source.
- **core:** `Analyser` (+ `AnalyserOptions`) — an `AudioProcessor` wrapping an
  `AnalyserNode` as a pass-through tap. Exposes `readFrequencies`/`readWaveform`
  with `createFrequencyBuffer`/`createWaveformBuffer` and `binCount`/`fftSize`,
  for audio visualizers. Poll it from a render loop, not an `effect()`.
- **docs/skill:** `choosing-playback.md` — decision flow plus per-primitive
  use/avoid and common mistakes for `Sampler`, `BufferPlayer`, and `FilePlayer`.
- **docs/skill:** `pixijs.md` — guide for pairing PixiJS with audiorective. No
  binding package is needed; core + `alien-signals` cover it. Documents the boot
  one-liner, the `effect`-vs-`ticker` decision, and the worked example
  `apps/pixi-visualizer`.

### Fixed

- **core:** `BufferPlayer.loop` setter now reapplies the loop window when toggled
  mid-play.
