# Widgets: constraints before variants (feat/affordance-widgets)

Evidence lives in ignored `blueprints/probes/affordance-widgets/` in the development worktree. C0 contains eight real-public-type tasks, three runs each; every sample has been read. Initial W6/W8 lack exact app-owned producer contracts, so their first results remain preclarification evidence. Clarified controls use explicit producer contracts, rather than adjusting host types to match generated answers. Raw results remain unchanged.

These existing decisions constrain every candidate:

- Widgets borrow audio/model owners. Detaching a view releases view resources and leaves shared playback, preview and authored data alive. `dispose()` is the lifecycle convention.
- Observable authored state stays on owner cells/params; `.value` reads track automatically. `readonlyCell(() => ...)` can project existing tracked getters without a mirrored store. Local gesture previews belong to a view and commit through owner commands once.
- Widget drawing and gestures remain independent of DAW runtime. Capability contracts are structural or type-only; widgets must not create an audio engine, analyser or transport to display already available data.
- Keep the existing mount/renderer/plugin layers. A declaration-only rewrite is not justified by the clean W1–W4 core paths. Extensions use attachment-owned listeners and cleanups, public geometry and view notifications.
- Keep seconds versus beats explicit and delegate musical projections/snapping to supplied functions. Seventh visible step is index 6; second scene is index 1. Waveform peak data remains audio-independent.
- Canceled gestures, lost capture, stale external replacements and disposal commit no authored edits. External updates retain mounted control identity/focus; stale previews may be canceled.
- Public API changes migrate every consumer and update type hints, docs, changelog and functional evals together. No compatibility overloads solely to keep superseded forms.

Measured questions to compare after both desire rounds: a meter over existing dBFS data versus PCM-only readers; direct reactive points/curve options versus explicit synchronization; readable/getter duration discoverability; tracked zoom scale versus a manual refresh; plugin geometry notifications and exclusive gesture composition. Runtime Escape/lost-capture failures are independently reproduced and require correction regardless of which declaration shape wins. Private type imports, grader mistakes, caller arithmetic, and missing producer context are recorded separately from missing toolkit capabilities.

## Effects verification corrections (2026-11-21)

- Real-type E1/E2 samples manually set smoothing 5/5 times even though the effects already default to 10 ms. Put this default in emitted parameter/class JSDoc (wet, Channel gain/pan, Send gain and the other controls actually using `SMOOTHING`); scheduled automation remains exact. No smoothing default changes.
- Real-type E2 samples exposed dry leakage from a fully wet Convolver send return while loading. Separate readiness from bypass: normal dry gain is always `1 − wet`, while readiness gates only the wet arm. Thus `wet: 1` stays silent during loading and after failure; partial wet keeps its declared dry proportion, including scheduled wet changes. Bypass always restores full dry, and ready/bypass transitions retain the existing click-free fades. Applied to the shared Effect base so async worklet/wasm and IR effects share one contract.
- E2 expectation 2 retains the original post-fader/mute/tail/return checks and adds: “The return is fully wet, including while its impulse response loads or fails, so it never duplicates the dry stems.” This strengthens the shared reverb-return behavior already requested; no behavior check is relaxed.

- Expressive build exposed TS2417 when a subclass chose its own static serialization type. Built-in `static readonly type` declarations use `string` rather than an inferred literal; a custom PingPongDelay subclass now compiles and round-trips with its own type name.
- A mixer that combines an owned `defineGraph` with `Channel.send()` crosses separate latency solves: the first consumer render had two send impulse peaks 240 samples apart. Using processor `connect()` consistently gives one aligned impulse without caller delay nodes. Put the graph-boundary requirement in `Channel.send` JSDoc and correct the effects guide example. Internal self-contained graphs still use `defineGraph`.
- Non-loop `TimeStretch.process()` must have zero wrapped margin; fixed a one-frame request/trim error and tested first-sample preservation at the worker boundary without claiming real Rubber Band DSP coverage. `EffectChain.restore()` catches throwing custom param binds as issues and rolls their signal back, continuing with later parameters.
- Saved Filter type strings are validated explicitly: Chromium silently ignores an invalid BiquadFilterNode enum assignment, which otherwise leaves the Param signal holding a value the node did not accept. The bind rejects invalid values, and restore reports the issue and restores the previous signal before applying later settings. The new `Effect: invalid filter type` message uses the existing Effect error route and has a reference-doc row.
- Repeated expressive preset morphs exposed another initialization edge: `EffectChain.restore()` wrote new detached params through smoothing when the context clock was already nonzero. At an offline suspend, Filter 1800 Hz / wet .3 read back as constructor defaults 350 Hz / wet 1 with no issues. Restore now initializes SchedulableParam values without smoothing and restores each smoothing setting in finally; first rendered samples match a constructor-configured reference, and later writes keep normal smoothing.
