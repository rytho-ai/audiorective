title: MCP
---

`@audiorective/daw/mcp` gives an AI agent the same project a person has open: it reads what the person selected, queries the song, applies one compound edit the person can undo in one step, listens to the result and saves. The agent never rewrites the `.dawproject` file; it reads a compact text summary and sends JSON operations.

```
 agent (Claude Code, Codex)
   │  MCP over stdio
   ▼
 server side   @audiorective/mcp          Node process the agent starts; relays tools/list and tools/call
   │  WebSocket (127.0.0.1:7777)
   ▼
 page side     @audiorective/daw/mcp      mcpTools(workspace) + connectMcpBridge(...); runs in the browser with the Workspace
```

All logic is in `mcpTools`. The MCP server only relays `tools/list` and `tools/call`, so any other transport (a test, an in-page chat box) calls the same tools.

## Wire it up

```ts
import { mcpTools, connectMcpBridge } from "@audiorective/daw/mcp";

const tools = mcpTools(workspace, {
  save: (bytes, name) => download(new Blob([bytes]), name), // the page decides where a saved file goes
});
const bridge = connectMcpBridge(tools, "ws://127.0.0.1:7777"); // reconnects with backoff
// bridge.close() when the page unmounts
```

Run the server and register it with the agent (see `packages/mcp/README.md`):

```sh
claude mcp add audiorective -- npx -y @audiorective/mcp --port 7777
# Codex, in ~/.codex/config.toml:
# [mcp_servers.audiorective]
# command = "npx"
# args = ["-y", "@audiorective/mcp", "--port", "7777"]
```

`mcpTools(workspace, options?)` returns `readonly McpTool[]`. Each tool is `{ name, description, inputSchema, call(args) }` and `call` never rejects: bad input, a conflict or a failure comes back as `{ content, isError: true }` so the agent can read it. `McpToolResult` is `{ content: string, isError?: boolean, data?: unknown }`; `content` is what the agent reads and `data` is the same facts as a value.

## Clip windows

`read_project` (timeline `clips` and `slotClips`) and `find` give every clip the part of its content that plays, as flat fields: `sourceOffset`, `sourceLength` (audio only; empty for MIDI), `loopStart` and `loopEnd` (empty without a loop) and `stretchRatio` (audio only: timeline seconds per second of audio when the clip is time-stretched, empty otherwise; whether its pitch is approximate is in `workspace.cells.warnings`, not in the clip). A MIDI clip's values are content beats: it plays content `[sourceOffset, sourceOffset + durationBeats)`, so `sourceOffset` 4 on a clip starting at beat 0 means its first bar is content beat 4 (a value below 0 means empty space before the content). An audio clip's values are seconds of the recording: `sourceOffset` is where in the recording the clip begins and `sourceLength` the recording's total length.

**Positions.** `atBeat` is project beats (quarter notes from the start), `atSeconds` is project seconds; an operation that takes a position takes `atBeat` or `atSeconds`, and a row giving both is accepted when they name the same moment at the tempo map as it is at that step of the request (within 1e-6 s) and rejected with a `disagree` reason otherwise. A position in beats is converted with that tempo map, so put tempo changes first in `ops`. Note `start`, `sourceOffset` and `setClipLoop` beats are content beats. Volumes, sends and gains are linear gain (0 or more, 1 is unity, no upper limit); `pan` is -1 (left) to 1 (right).

**Selecting clips, tracks and scenes.** `clip` is `{ clipId }` or `{ fromCopy: "<as name>", trackName? }`. A `trackId` or `sceneId` is an ID or `{ fromCopy: "<as name>" }`. An operation that makes something takes `as: "<name>"` (unique in the request); later steps refer to it with `fromCopy`. The receipt lists what was made: `created` (clip IDs), `createdNotes`, `createdTracks: [{ id, as? }]`, `createdScenes: [{ id, as? }]` and `copies` (per `as` name: `[{ from?, id, trackId }]`). It also lists what else changed: `changed` and `removed` clip IDs, `changedTracks` (name, level, mute, solo, pan, inserts, macros, routing, devices or level automation), `removedTracks`, `changedScenes` (renamed or moved), `removedScenes`, and `song`, any of `"tempo"`, `"timeSignature"`, `"markers"`, `"title"` and `"masterVolume"`; each is an empty list when nothing of that kind changed.

**Replacing operations.** `setTempoChanges`, `setTimeSignatureChanges`, `setMarkers`, `setVolumeAutomation`, `setControllerLane`, `setAudioClipGainAutomation`, `setTrackEffects`, `setTrackRackPreset` and `setTrackRouting` replace the whole list: read the current one from `read_project` first (a curve of more than 32 points shows only its count and ends there; `read_automation` returns its points). The rows `read_project` shows go back unchanged, and a list equal to the current one is a `noop`. A field an operation does not take is rejected with the allowed list. Rejection `code` is one of `invalid-operation` (malformed field), `clip-not-found`, `ambiguous-clip`, `note-not-found`, `track-not-found`, `scene-not-found`, `device-not-found`, `overlap` (a moved or created clip ends on another) or `edit-failed` (the model refused, with its message).

**Device parameters.** `read_device_params` returns the same row shape for a WebCLAP plug-in and a built-in effect, so an agent does not tell them apart: read `{ id, value, min, max, step?, unit?, text? }`, then send `{ type: "setDeviceParameter", deviceId, parameterId: id, value, expectedValue: <the value read> }`. A built-in effect's `deviceId` is `trackId:slotId` (slot IDs are unique only within a track; `read_project` `effectDevices` lists them) and the operation writes the same data `setTrackEffects` does; a parameter that a rack macro drives is refused (set the macro). The value is song content: one undo step with the rest of the request, saved with the file, heard by the running page without a rebuild. A parameter the plug-in moves by itself (its own automation, the person turning its GUI) is not an undo step, and the value it reports now is what `read_device_params` shows and what `expectedValue` is compared with.

**Playback.** Mixer, tempo, marker, clip, scene and device-order changes are light edits and reach playback (`playback.status` `applied`). Adding a track, or removing a track that has been playing, is structural: the receipt reports `playback.status: "needs-sync"` and `needsSync: true` until the page runs `workspace.sync()` (removing a track that was only just added restores the running topology and plays at once).

## The TOON summary

`read_project` encodes a flat view of `project.overview()` with `@toon-format/toon`: uniform lists such as `clips` become one header and one row per clip, which costs far fewer tokens than the same JSON. Automation curves are one entry per track or clip with its `points` (`controllerLanes` has one entry per lane, with its `expression`, `channel` and, for `channelController` and `polyPressure` only, `controller`; the other expressions have none, as `setControllerLane` takes none there), and a curve of more than 32 points shows only its `count` and the `first` and `last` position (call `read_automation` for the points). Every position row shows `atBeat` and `atSeconds`, at full precision, so a row can be sent back to the operation that replaces the list. The `selection` block is what the person has selected (`selectionFor(project)`): `trackId`, `clipIds`, `openClipId`, `noteIds`, `range`. "This clip" or "the part I marked" means that block. The selection is not saved, not undoable and does not change `version`.

## Edits, conflicts and undo

`apply_edits` takes the operations of `project.applyEdits` (see [Edit a project as one undoable step](./daw.md#edit-a-project-as-one-undoable-step)) with the `version` the agent last read as `expectedVersion`. The undo label is `Agent: <label>`, so the person presses Undo once in the app and the whole agent edit goes.

- `applied`: the edit is in the project. The receipt waits for the running Workspace to apply it, then reports `playback: { status, inPlayback, needsSync, error }`. `inPlayback: true` means it is audible now. `needsSync: true` means a structural change (a track or device) waits for `workspace.sync()`, which the page runs when the person accepts a glitch; the agent should say so instead of claiming it plays.
- `noop`: the edit ran but left the project as it was (for example a volume already at that value); there is no undo step and the receipt says so.
- `conflict`: the person changed the project after the agent read it, or a `setDeviceParameter` carried an `expectedValue` the parameter no longer holds (the `reason` names the current value). Nothing changed and the person's edit is kept. The receipt carries `currentVersion`; the agent calls `read_project` (or `read_device_params`), re-plans and sends again.
- `rejected`: the request is invalid (`code`, `reason`, `opIndex`). Nothing changed.

**Tempo changes travel with a copy.** `copyRange` (and so a duplicated section) copies the tempo changes inside the range along with the clips. Copying beats 32-48 to 48 with `placement: "insert"` where the range holds a change to 90 BPM at beat 40 leaves a second change to 90 BPM at beat 56, and the copy plays at its own tempo. The agent should report it, for example "the copied chorus repeats its tempo change at beat 56", and not call the copy tempo-neutral.

**`version` only counts up.** Every commit, including the person's Undo, produces a new, higher `version`; undo never restores an older number. After an undo, the agent compares content (`read_project` again, or the receipt's `changed` ids), not version numbers, and uses the new `version` as `expectedVersion`.

`run_operation` runs one of the app's named operations (the `operations` list in `read_project`, each with its `input` JSON Schema) as one Undo step labelled by the operation itself (the receipt's `undoLabel`). Fields outside the schema, a missing required field or a wrong type return an error that quotes the schema. `status: "noop"` means the project did not change (no undo step). Pass `expectedVersion` to refuse after a human edit. Agents have no undo tool: only the person undoes.

**App data and queries.** An app's extension data is not shown unless its `defineExtension` has a `summary`: `read_project` then lists `extensions: [{ id, summary }]`, the app's own picture of its data (for a pattern DAW, which pattern sits at which bars and which clip ids). Use it to find the app's concepts instead of guessing from clip names. An operation with `readOnly: true` in `operations` is a query: `run_operation` returns `status: "read"`, the `result` and the current `version`, makes no undo step and never needs `expectedVersion`. See [Extensions](./daw.md#extensions).

## Listening

`listen` renders a range of the mix offline (every track, device and effect; playback keeps going) with `renderMixRange` and returns numbers, plus a short WAV when the app allows it:

```json
{
  "status": "rendered",
  "version": "…",
  "startSeconds": 4,
  "durationSeconds": 4,
  "peakDbFS": -9.1,
  "loudnessLUFS": -22.4,
  "silentSpans": [{ "startSeconds": 6, "endSeconds": 6.5 }],
  "seams": [{ "beat": 16, "hasClick": false, "jump": 0.0021, "localJump": 0.0019 }],
  "historyTruncated": false
}
```

**One track, or a few.** `trackIds` (ids from `read_project`) makes only those tracks sound, so the agent can find which track clicks or is too loud. Each still plays through its own devices, instruments, inserts, volume, pan and automation, the bus it outputs to and the master, so the audio equals a live solo of the same tracks. Send returns (effect buses a selected track feeds) are included, as in a solo, and selecting a bus brings in the tracks that feed it. A muted track stays silent, and the project's own solo flags are ignored for the render. The numbers measure the sum of those tracks, the result echoes `trackIds`, and the song, its version and playback are untouched. An id that is not a track returns an error naming it.

**Hearing it.** The default is numbers only. When the app passes `mcpTools(workspace, { listenAudio: { maxSeconds } })`, a call with `audio: true` also returns a 16-bit stereo WAV of the start of the range, at most `maxSeconds` long, as an MCP audio content block next to the JSON (`McpToolResult.audio` carries it as base64 over the bridge); when the range is longer, `audioNote` says how much audio came with it, and the numbers still cover the whole range. Audio leaves the page like an export does, so it also needs the `export` permission (see Security and permissions): with `allow: ["read"]` a request with `audio: true` returns the numbers and an `audioNote` saying audio needs the export permission. Without `listenAudio` it returns the numbers and an `audioNote` saying audio is not enabled. `maxSeconds` must be a finite number above 0. It is off by default because audio is the largest and most private payload a tool can send: it goes to the agent's model provider and costs about 192 KB per second at 48 kHz.

`peakDbFS` is `null` for digital silence and `loudnessLUFS` is `null` under 400 ms. `silentSpans` are stretches at least `minSilenceSeconds` (default 0.1) below `silenceDb` (default -60), in project seconds. `seams` check the beats in `seamBeats` for clicks, such as the joins of an edit. A stale `expectedVersion` returns `status: "conflict"`.

## Bridge protocol

Frames are JSON text. The server sends, the page answers with the same `id`:

| Server to page                                  | Page to server                                                      |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| `{ "id": 1, "method": "list" }`                 | `{ "id": 1, "result": [{ "name", "description", "inputSchema" }] }` |
| `{ "id": 2, "method": "call", "name", "args" }` | `{ "id": 2, "result": { "content", "isError?", "data?" } }`         |
| anything it cannot serve                        | `{ "id": 2, "error": "message" }`                                   |

`connectMcpBridge(tools, url, options?)` returns `{ close(), connect() }`. It reconnects with a doubling delay (`reconnectMs` 500, `maxReconnectMs` 10000) and reports `onStatus(connected)`; a `WebSocket` constructor that throws (a bad URL) is reported as `onStatus(false)` and retried like any failed connection. `@audiorective/mcp` accepts one page at a time and listens on `127.0.0.1` only.

**Plain HTTP.** A request that is not a WebSocket upgrade (a browser tab, `curl`) gets `426 Upgrade Required` with `Connection: close` and a one-line body.

**Two pages: the newest wins.** When a second page connects, the server closes the first with WebSocket close code `4000` and reason `replaced by another page`. The bridge does not reconnect on that code (two pages that reconnected would take turns replacing each other forever): it calls `options.onReplaced()` and stays closed until the page calls `bridge.connect()` or reloads. Show the person a "taken over by another page" state with a button for `connect()`.

**Listing before the page connects.** `tools/list` waits up to `--wait-ms` (default 10000) for a page, then answers with an empty list. A page that is connected but fails to answer `tools/list` (it errors, leaves or times out) makes `tools/list` fail with that message instead of returning an empty list. The server declares `tools.listChanged` and sends `notifications/tools/list_changed` when a page connects or disconnects, and its `instructions` tell the agent that an empty list means no page is connected yet. `tools/call` without a page returns the `No audiorective page is connected…` error at once.

## Security and permissions

The threat is another web page in the same browser opening a WebSocket to the local server to take the DAW page's place or read the agent's tool arguments. Browsers set `Origin` on every WebSocket handshake and a page cannot forge it, so the server refuses any page whose **origin** is not allowed; a process on the same machine can skip `Origin`, but it already has local access. A **pairing token** is optional defence in depth, and the app limits what the agent may do with **permissions**.

**Origins.** The handshake carries the page's `Origin` header. By default the server accepts only loopback origins on any port: `http://localhost:*`, `http://127.0.0.1:*` and `http://[::1]:*`, which covers a page on a local dev server. A page from any other origin, or a client that sends no `Origin` (a script, not a browser), gets HTTP 403 before any frame, and the server writes one line to stderr naming the origin (never the token). Name other origins with `--allow-origin` (repeatable; `scheme://host:*` means any port) or `allowedOrigins` in `PageBridge.listen`; `--allow-missing-origin` or `allowMissingOrigin` accepts a client with no `Origin`.

```sh
claude mcp add audiorective -- npx -y @audiorective/mcp --port 7777 --allow-origin https://app.example.com
```

**Pairing token (optional, off by default).** A server with no token accepts any page from an allowed origin. Add one when the page is served from a non-loopback origin (a LAN address or a tunnel) or the machine is shared: start the server with `--token <token>` or `AUDIORECTIVE_MCP_TOKEN=<token>` (22 or more letters, digits, `_` or `-`), or `--token auto` to make a random 256-bit token and print it on stderr (in code, `PageBridge.listen({ token })` and `createToken()`). The page then passes `connectMcpBridge(tools, url, { token })`. It travels as the WebSocket subprotocol `audiorective.token.<token>` next to `audiorective.v1`, not in the URL, so it stays out of request lines and logs; the server selects only `audiorective.v1`. The token is compared in constant time. "The newest page replaces the older one" applies only among pages that passed the checks, so a foreign page cannot displace the paired one.

```ts
declare const token: string; // for example from your bundler's environment variables
connectMcpBridge(tools, "ws://192.168.1.20:7777", { token });
```

A rejected page sees only a failed connection: `onStatus(false)` and a retry with backoff. Browsers do not show a WebSocket page the HTTP status, so check the server's stderr for the reason.

**Permissions.** `mcpTools(workspace, { allow })` limits the tools by category. Disallowed tools are not in the tool list; a call for one anyway gets `No tool named "…". This page serves: …`.

| Category     | Tools                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `read`       | `read_project`, `find`, `read_notes`, `read_automation`, `read_device_params`, `listen` (numbers), and an operation marked `readOnly` |
| `edit`       | `apply_edits`                                                                                                                         |
| `export`     | `save_as`, `export_midi`, `export_stems`, and the audio of `listen` (`audio: true`, when the app also passes `listenAudio`)           |
| `operations` | `run_operation` for the app's operations that change the project                                                                      |

`listen` with `audio: true` sends the song itself to the agent's model, so it is gated like an export: it returns sound only when `allow` has both `read` and `export` and the app passed `listenAudio`. The default is all four, so an app that does not pass `allow` keeps working; the origin check (and the token, when you set one) is the protection against other web pages, and `allow` is the app's own policy for an agent it trusts less. `allow: ["read"]` lets the agent look and run `readOnly` operations, nothing else: `run_operation` stays listed and refuses an operation that changes the project with a plain sentence, and `read_project` lists only the operations the agent may call. An unknown category name throws. Every tool declares its category where it is defined, and a test fails for a tool without one, so a new tool cannot skip the policy.

| Message or result                                                                    | Cause                                                                    | Fix                                                                                |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| `allowedOrigins entry "…" is not an origin. Use …`                                   | An `allowedOrigins` or `--allow-origin` value is a path, `*` or a host   | Use `scheme://host`, `scheme://host:port` or `scheme://host:*`                     |
| `The pairing token must be at least 22 characters…`                                  | `--token`, `token` or `AUDIORECTIVE_MCP_TOKEN` is too short or malformed | Use `--token auto`, or 22 or more of `A-Za-z0-9_-`                                 |
| `connectMcpBridge: token must be at least 22 characters…`                            | The page's `token` option is malformed                                   | Pass the token the server requires                                                 |
| `mcpTools: unknown permission "…" in allow. Use …`                                   | `allow` holds a name that is not a category                              | Use `read`, `edit`, `export` or `operations`                                       |
| `mcpTools: listenAudio.maxSeconds must be a finite number greater than 0.`           | `listenAudio.maxSeconds` is missing, zero, negative, NaN or infinite     | Pass the longest audio, in seconds, that `listen` may return                       |
| `This app does not let the agent run operation "…" because it changes the project …` | `run_operation` with `allow` lacking `operations`                        | Tell the person; the app owner adds `operations` to `allow` if the agent may do it |
| `This app does not let the agent read through operation "…" …`                       | A `readOnly` operation with `allow` lacking `read`                       | Tell the person; the app owner adds `read`                                         |
| `No tool named "…". This page serves: …`                                             | The tool is outside `allow`, or does not exist                           | Use a listed tool; ask the person if the action needs a wider `allow`              |

## Common errors

| Message or result                                           | Cause                                                                                                                     | Fix                                                                       |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
